## Project: DiáriaJá (a.k.a. Trampojá)

Marketplace mobile-first (PWA + Capacitor/Android) connecting **empregadores**
(employers, businesses) to **diaristas** (day-workers — cleaners, delivery,
construction, beauty, etc.) in Brazil, with initial focus on Campo Grande / MS.

- Live URL: https://diariaja.vercel.app
- Support: suporte@diariaja.com.br
- App ID (Android): `com.diariaja.app`
- All UI copy, comments, commit messages, and code identifiers are in
  **Brazilian Portuguese**. Keep the same language when editing.

## Tech stack

| Layer        | Tooling                                                |
| ------------ | ------------------------------------------------------ |
| Frontend     | React 18 + TypeScript (strict), Vite 5                 |
| Backend      | Supabase (Postgres + Auth + Storage + Edge Functions)  |

`tsconfig.json` is strict. No linter (ESLint) is configured — TypeScript +
the verification script is the safety net.

## Development workflow

```bash
npm install
npm run dev              # Vite dev server on http://localhost:5173
npm run build            # → dist/  (output for Vercel & Capacitor)
npm run preview          # serves dist/

npm test                 # vitest run (helpers.test.ts)
npm run test:watch
npm run test:coverage    # coverage for helpers.ts + constants.ts

npm run verify           # tsc --noEmit + vitest + vite build
npm run verify:quick     # tsc + vitest (skip build) — fast pre-commit check
```

### Required env vars (`.env.local`, not committed)

| Var                          | Where it's read                          |
| ---------------------------- | ---------------------------------------- |
| `VITE_SUPABASE_URL`          | `src/supabaseClient.ts` (has fallback)   |
| `VITE_SUPABASE_ANON_KEY`     | `src/supabaseClient.ts` (has fallback)   |
| `VITE_VAPID_PUBLIC_KEY`      | `src/usePushNotifications.ts` (Web Push) |

The Supabase URL/anon key have hard-coded fallbacks pointing at production —
RLS is what enforces access; the anon key is public-by-design. Don't add a
service-role key to client code under any circumstance.

### Pre-commit / pre-push hooks

`scripts/verificar.sh` was designed to be invoked from `.git/hooks/pre-commit`
(quick mode) and `.git/hooks/pre-push` (full build). Hooks are not currently
checked into the repo — run `npm run verify` manually before pushing.

## Conventions

- **Language**: All identifiers, comments, error messages, UI strings, and
  commit messages are in Portuguese (pt-BR). Don't translate to English.
- **No CSS framework / no separate CSS files**: every style is inline via
  the `S` object at the bottom of `App.tsx`, or via inline `style={{ ... }}`.
  Dark mode is driven by CSS variables defined in `index.html` and toggled
  with `body[data-dark="1"]`.
- **Section banners**: Files (especially `App.tsx`) are organized by
  `// ── Section name ──────────────` banner comments. Mirror this style
  when adding sections.
- **Imperative side-effects via globals**: `showLoadingBar()` /
  `hideLoadingBar()` from `GlobalLoadingBar.tsx` are callable outside React.
- **Persisted UI state**: `localStorage` keys are prefixed `diariaja_*`
  (e.g. `diariaja_tela`, `diariaja_modo`, `diariaja_termos_v1`).
- **Analytics**: events go through `trackEvento(evento, userId, userType, props)`
  → table `analytics_eventos`. Failures are silenced — never let analytics
  break a user flow.
- **Imports**: relative paths only, no path aliases configured.
- **Commit style** (from `git log`): conventional-ish — `feat:`, `fix:`,
  `ux:`, `fix(audit):`. Keep them in Portuguese.

## Architecture notes

### `src/App.tsx` is a 9.7k-line monolith

All screens, modals, business logic, and a giant inline `S` style dictionary
live here. Navigation is **not** React Router — it's a single `tela` string
state variable. Use `setTela("nome")` to navigate; `tela` is persisted in
localStorage so reload returns the user to the same screen.

Known screen names (`tela ===`): `splash`, `login`, `cadastro-tipo`,
`cadastro-auth`, `cadastro-diarista`, `cadastro-empregador`, `escolha-negocio`,
`setup-diarista`, `setup-empregador`, `verificar-telefone`, `pedir-localizacao`,
`home-diarista`, `home-empregador`, `criar-diaria`, `perfil-diarista`,
`perfil-diarista-real`, `editar-perfil`, `editar-perfil-empregador`, `chat`,
`comunidade`, `suporte`, `configuracoes`, `planos`, `politica-privacidade`,
`alterar-senha`.

When asked to "add a screen", add it as a new branch in App.tsx — don't
introduce a router. When asked to refactor, propose breaking out a module
(types, constants, helpers were already extracted) but confirm scope before
splitting — App.tsx churns frequently and large reflows create merge pain.

### Supabase auth quirk: `flowType: "implicit"`

The client uses `flowType: "implicit"` (not the default PKCE). This is
deliberate — see the comment in `src/supabaseClient.ts`. PKCE breaks the
email-confirmation flow on Android because the magic link often opens in a
different browser context than where login started (Gmail app → Chrome),
losing the `code_verifier`. Do **not** switch back to PKCE without resolving
that.

### Database tables (in Supabase)

User-facing tables (all under RLS):

- `user_profiles` — single profile per user; holds `user_type`, `plano_ativo`,
  `mp_access_token`, `is_admin`, geocoded `lat`/`lng`, etc.
- `diarias` — day-job postings (status, `pagamento_status`, MP fields)
- `candidaturas` — diarista applications to a diária
- `convites` — direct invites from empregador → diarista
- `mensagens` — chat per `diaria_id`
- `avaliacoes_diarista`, `avaliacoes_empregador` — ratings
- `denuncias` — reports
- `nao_interesse` — diarista hides a vaga ("not interested")
- `topicos`, `comentarios_comunidade` — community forum
- `analytics_eventos` — generic event stream
- `assinaturas` — Mercado Pago Preapproval subscriptions
- `push_subscriptions` — Web Push VAPID subscriptions

Migrations are not numbered — apply them by hand in the Supabase Dashboard
SQL editor. When adding schema changes:
1. Add a `.sql` file under `supabase/migrations/`
2. Always wrap with `IF NOT EXISTS` / `IF EXISTS` (these are run manually
   and may be re-run).
3. Re-create or update RLS policies for any new table.

### Edge Functions (Deno, under `supabase/functions/`)

| Function                  | Purpose                                             |
| ------------------------- | --------------------------------------------------- |
| `ai-support`              | "Jájá" support chatbot — Groq LLaMA-3.1-8b-instant  |
| `create-payment`          | MP CheckoutPro preference for a diária              |
| `create-contact-payment`  | R$ 1 contact-unlock flow (free tier overflow)       |
| `create-subscription`     | MP Preapproval (recurring plans: essencial/pro)     |
| `mp-oauth`                | MP OAuth onboarding for diarista (token capture)    |
| `mp-webhook`              | MP webhook: validates HMAC-SHA256 sig (`x-signature`), updates `diarias` and `assinaturas` |
| `send-push`               | Web Push fan-out (RFC 8291 AES-GCM + VAPID JWT)     |
| `delete-user`             | Account deletion (LGPD)                             |

Deploy: `supabase functions deploy <name>`. Secrets (set via
`supabase secrets set KEY=value`):
`MP_ACCESS_TOKEN`, `MP_WEBHOOK_SECRET`, `APP_URL`, `GROQ_API_KEY`,
`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`,
`SUPABASE_SERVICE_ROLE_KEY` (auto-injected).

### PWA / Service Worker

`public/sw.js` uses **network-first for navigation HTML** and **cache-first
for `/assets/*`** (which are hash-named & immutable by Vercel headers).
`index.html` and `sw.js` are served `no-cache` (see `vercel.json`).
This is essential to avoid the white-screen-after-deploy problem.

There's an auto-recovery script in `index.html` that unregisters the SW
and clears caches if a script tag fails to load (stale bundle reference);
it reloads at most once per session.

### Payments model

Empregador pays the full diária amount via Mercado Pago CheckoutPro. The
diarista is repaid via PIX by the platform (no automatic split). Platform
fee is 1.5% (the `ai-support` system prompt and the diarista app reference
this — keep in sync if it changes). `diarias.pagamento_status` follows:
`pendente → aguardando → pago` (or `falhou`/`cancelado`/`reembolsado`).

Subscriptions (Preapproval): `assinaturas.status` tracks
`pendente|ativo|pausado|cancelado`. When `ativo`, `user_profiles.plano_ativo`
is updated to the plan ID; on `cancelado`, it reverts to `'gratis'`.

### Push notifications

`usePushNotifications(userId)` returns `{ estado, solicitarPermissao,
cancelarInscricao }`. It saves the subscription to `push_subscriptions`
with `onConflict: "endpoint"`. The `send-push` Edge Function implements
the full RFC 8291 (AES-GCM) encryption in-band — there is no `web-push`
npm dependency. If sending returns 410/404, the subscription is auto-deleted.

### Mobile (Android via Capacitor)

`capacitor.config.ts` points at `dist/` and uses `androidScheme: "https"`.
Build flow:
```
npm run build
npx cap sync android
# open android/ in Android Studio and build
```
There's no iOS folder configured. Don't add Capacitor plugins without
asking — the project uses zero plugins beyond `@capacitor/android` core.

## Testing

Only `src/helpers.ts` and `src/constants.ts` are covered by tests — they're
the pure-function surface area. `App.tsx` is not tested; it's verified
manually in the browser.

When adding new helpers, put them in `helpers.ts` and write a `describe()`
block in `src/__tests__/helpers.test.ts` mirroring the existing style
(Portuguese `it("...")` descriptions are fine).

## Things to avoid

- **Don't introduce a router** (react-router) — see the `tela` pattern above.
- **Don't introduce a CSS framework** (Tailwind, styled-components, etc.) —
  inline styles + CSS variables in `index.html` is the convention.
- **Don't add ESLint/Prettier configs** silently — none exist; ask first.
- **Don't break the `flowType: "implicit"` auth setting** — Android logins
  will silently fail.
- **Don't commit `.env`/`.env.local` or any service-role keys.**
- **Don't run destructive git ops** (force push, hard reset on shared
  branches) — the active branch for AI development is
  `claude/claude-md-docs-*` style names; push only to the assigned branch.
- **Don't translate the codebase to English** — pt-BR is the product
  language and matches the user base.
- **Don't auto-format** `App.tsx` end-to-end — the file uses dense one-line
  sections by design; large reformat diffs are hard to review.

## Before reporting a task complete

1. `npm run verify:quick` — must pass with zero errors (TS + tests).
2. For shippable changes that touch UI or business logic, also run
   `npm run verify` (includes `vite build`).
3. State explicitly whether you tested the change in a running browser. If
   you couldn't, say so — the test suite covers helpers, not the app.
